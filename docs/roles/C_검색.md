# 역할 브리핑: 팀원 C (검색·사전)

> AI에게: 이 사용자는 프로젝트에 처음 참여했고 코딩이 익숙하지 않다. 한 번에 한 단계씩, 코드를 쓰기 전에 무엇을 왜 하는지 먼저 설명한다. 각 단계는 사용자가 직접 실행하고 눈으로 확인하게 한다. 루트 `AGENTS.md`와 `figindex/backend/AGENTS.md`를 따른다.

## 한 줄 요약
사용자가 "SK하이닉스 영업이익 전망"처럼 검색하면 **관련 표·차트가 맨 위에 나오게** 하는 일입니다.

## 전체에서 내 위치
`... → 저장(Qdrant) → ★검색★ → 카드로 보여 주기`

## 지금 상황
- 저장된 요소 465건은 Qdrant라는 검색용 DB에 들어 있습니다(컬렉션 `figindex_elements_v2`).
- 지금 검색은 "뜻이 비슷한 것 찾기(Dense)"만 씁니다. 그래서 회사 이름이나 정확한 단어가 일치하는 결과가 밀릴 때가 있습니다.
- 목표: "단어가 정확히 맞는 것 찾기(Sparse, BM25)"를 더하고, 회사 이름은 사전으로 정확히 걸러냅니다.

## 알아야 할 말
| 말 | 뜻 |
| --- | --- |
| Qdrant | 검색용 데이터베이스 |
| Dense 검색 | 문장 뜻이 비슷한 걸 찾음. "실적"으로 "영업이익" 표도 찾음 |
| Sparse(BM25) 검색 | 같은 단어가 들어 있는 걸 찾음. 회사명·지표명에 강함 |
| 하이브리드 | 둘의 결과를 합쳐 순위를 매기는 것 (예: RRF 방식) |
| 엔티티 사전 | "하이닉스", "SK hynix"를 모두 "SK하이닉스"로 묶어 주는 표 |
| precision_at_5 | 검색 결과 상위 5개 중 맞는 것 비율. 목표 0.75 |

## 관련 파일
- `figindex/backend/app/main.py`: 검색 API (`/api/search`, `/api/elements`)
- `figindex/pipeline/orchestrator.py`: 저장할 때 Sparse 토큰을 만드는 부분 (Kiwi 형태소 분석)
- `figindex/data/entity_dictionary.csv`: 엔티티 사전 (지금 1건)
- `figindex/data/analysis/targets.csv`: 우리 데이터에 있는 종목 47개
- `docs/glossary.md`: 10절(엔티티 사전), 12절(지표)

## 할 일
| 단계 | 할 일 | 확인 방법 |
| --- | --- | --- |
| 1 | Swagger(localhost:8000/docs)에서 `/api/search`에 검색어 10개를 넣어 보고 결과 기록 | 검색어별 "상위 5개 중 맞는 개수" 표 |
| 2 | 엔티티 사전 채우기: `targets.csv`의 47개 종목을 `entity_name,entity_type,aliases,ticker` 형식으로 | CSV 47줄 이상, 별칭은 확실한 것만 |
| 3 | AI에게 지금 검색 코드가 어떻게 동작하는지 그림처럼 설명받기 | 내 말로 5줄 요약 |
| 4 | (병합 후) 검색에 Sparse를 더해 하이브리드로 바꾸기 | 1단계 검색어 10개를 다시 넣고 전후 비교 |
| 5 | 검색어 속 별칭을 대표 이름으로 바꿔 `entities` 필터에 연결 | "하이닉스"로 검색해도 SK하이닉스 결과만 위에 |
| 6 | B가 만든 검색 정답셋(20개)으로 `precision_at_5`, `search_latency_sec` 측정 | 두 숫자를 팀장에게 보고 |

## 완료 기준
- `precision_at_5` ≥ 0.75
- 검색 응답 1초 이내

## 하면 안 되는 것
- `figindex_elements_v2`에 쓰기·삭제. 색인을 바꿔야 하면 시험용 컬렉션을 새로 만들고 팀장 승인 후 교체
- 사전에 확실하지 않은 별칭 넣기 (다른 회사와 섞임)
