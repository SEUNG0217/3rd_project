# 역할 브리핑: 팀원 1 (업로드 — 서버와 화면)

> AI에게: 이 사용자는 프로젝트에 처음 참여했고 코딩이 익숙하지 않다. 한 번에 한 단계씩, 코드를 쓰기 전에 무엇을 왜 하는지 먼저 설명한다. 각 단계는 사용자가 Swagger나 브라우저에서 직접 확인하게 한다. 루트 `AGENTS.md`, `figindex/backend/AGENTS.md`, `figindex/frontend/AGENTS.md`를 따른다.

## 한 줄 요약
사용자가 **PDF를 올리고 → 처리가 어디까지 됐는지 보고 → 검수한 기록이 남는** 흐름을 서버(FastAPI)와 화면(Next.js) 양쪽으로 만드는 일입니다. 서버와 화면을 한 사람이 맡아서 서로 기다릴 일이 없습니다.

## 전체에서 내 위치
`★PDF 업로드★ → 오려 내기 → AI 읽기 → 저장 → ★검수 기록★`, 그리고 업로드·진행률·검수 화면

## 지금 상황
- 서버: 조회 API(목록·상세·검색·필터)와 검수 API는 있음 (`figindex/backend/app/main.py`). 업로드·진행률 API, 검수 기록 저장은 없음.
- 화면: 갤러리·상세·검수 탭·비교 모달은 있음. 업로드·진행률 화면은 없음.
- 데이터 모양은 이미 정해져 있음: `figindex/shared/schemas.py`의 `Batch`, `Document`, `DocStatus`, `ReviewLog`, `ReviewAction`

## 알아야 할 말
| 말 | 뜻 |
| --- | --- |
| API | 화면이 서버에 보내는 요청 주소. 예: `GET /api/elements` |
| Swagger | `localhost:8000/docs`. API를 버튼으로 눌러 시험하는 화면 |
| Batch | 한 번에 올린 PDF 묶음. `batch_id`로 구분 |
| doc_hash | 파일 내용으로 만든 지문(SHA-256). 같으면 이미 올린 파일(중복) |
| doc_status | 문서 처리 상태: 업로드됨 → 처리 중 → 완료/실패/중복 |
| ReviewLog | 검수자가 승인·수정·반려한 기록. 지우지 않고 쌓기만 함 |
| mock | 서버가 아직 없을 때 화면에서 쓰는 가짜 데이터 |

## 할 일
| 단계 | 할 일 | 확인 방법 |
| --- | --- | --- |
| 1 | Swagger에서 기존 API를 눌러 보고, 화면(localhost:3000)에서 검색 → 상세 → 원문 보기 → 비교 → 검수 탭을 따라 해 보기 | API 표 1장 + 화면에서 불편한 점 목록 |
| 2 | AI에게 `Batch`, `Document`, `ReviewLog`를 예시 데이터로 설명받기 | 내 말로 각 3줄 요약 |
| 3 | 저장 방식 제안: 문서·묶음·검수 기록을 어디에 저장할지 (후보: SQLite 파일 1개) | 팀장에게 제안 → 결정 |
| 4 | `POST /api/batches`: PDF 여러 개 받기 → 파일 저장 → `doc_hash`로 중복 판정 → `Batch`·`Document` 저장 (파이프라인 실행은 아직 안 함) + 업로드 화면(끌어다 놓기, 파일 목록)을 이 API에 연결 | 화면에서 PDF 2개 올리면 목록에 보이고, 같은 파일 다시 올리면 "중복" |
| 5 | `GET /api/batches/{batch_id}`: 소속 문서들의 `doc_status`를 세어 진행률 반환 + 화면에 문서별 상태를 한국어로 표시 (glossary 5절) | 업로드한 묶음의 진행률이 화면에 보임 |
| 6 | 검수 API가 처리할 때마다 `ReviewLog` 한 줄 추가 | 시험용 컬렉션에서 승인 1번 → 기록 1줄 |
| 7 | 검수 탭 단축키: `A` 승인, `R` 반려, 다음 항목으로 자동 이동 | 키보드만으로 3건 처리 (시험용 컬렉션) |
| 8 | 업로드 후 `BackgroundTasks`로 파이프라인을 실행하고 단계마다 `doc_status` 갱신 | PDF 1건 올리고 완료까지 상태가 바뀌는 것 확인 (시험용 컬렉션) |

## 완료 기준
- 화면에서 PDF 업로드 → 진행률 → 완료까지 클릭만으로 진행
- 10페이지 PDF가 업로드부터 완료까지 15초 이내 (`doc_latency_sec`)
- 새 API는 Swagger에서 시험 가능, 바뀐 내용은 `docs/migration/api_changes.md`에 기록

## 하면 안 되는 것
- `job_id`, `upload_id` 같은 이름 (→ `batch_id`)
- `ReviewLog` 수정·삭제 API
- 실제 서비스 컬렉션(`figindex_elements_v2`)에서 검수·업로드 시험 (→ `.env`의 `QDRANT_COLLECTION`을 시험용으로 바꾸고 시험)
- 화면에서 API 키를 camelCase로 바꾸기, 컴포넌트 안에 타입 따로 선언하기 (→ `app/lib/types.ts`)
