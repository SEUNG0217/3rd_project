# 역할 브리핑: 팀원 2 (검색)

> AI에게: 이 사용자는 프로젝트에 처음 참여했고 코딩이 익숙하지 않다. 한 번에 한 단계씩, 코드를 쓰기 전에 무엇을 왜 하는지 먼저 설명한다. 각 단계는 사용자가 직접 실행하고 눈으로 확인하게 한다. 루트 `AGENTS.md`와 `figindex/backend/AGENTS.md`를 따른다.

## 한 줄 요약
사용자가 "SK하이닉스 영업이익 전망"처럼 검색하면 **관련 표·차트가 맨 위에 나오게** 하고, 그게 얼마나 잘 되는지 점수로 증명하는 일입니다.

## 전체에서 내 위치
`... → 저장(Qdrant) → ★검색★ → 카드로 보여 주기`

## 지금 상황
- 저장된 요소 465건은 Qdrant라는 검색용 DB에 있습니다(컬렉션 `figindex_elements_v2`).
- 지금 검색은 "뜻이 비슷한 것 찾기(Dense)"만 씁니다. 회사 이름이나 정확한 단어가 일치하는 결과가 밀릴 때가 있습니다.
- 목표: "단어가 정확히 맞는 것 찾기(Sparse)"를 더하고, 회사 이름은 사전으로 정확히 걸러 냅니다.

## 알아야 할 말
| 말 | 뜻 |
| --- | --- |
| Qdrant | 검색용 데이터베이스 |
| Dense 검색 | 문장 뜻이 비슷한 걸 찾음. "실적"으로 "영업이익" 표도 찾음 |
| Sparse(BM25) 검색 | 같은 단어가 들어 있는 걸 찾음. 회사명·지표명에 강함 |
| 하이브리드 | 둘의 결과를 합쳐 순위를 매기는 것 (예: RRF 방식) |
| 엔티티 사전 | "하이닉스", "SK hynix"를 모두 "SK하이닉스"로 묶어 주는 표 |
| 검색 정답셋 | 검색어마다 "이 요소들이 나와야 맞다"를 사람이 적어 둔 목록 |
| precision_at_5 | 검색 결과 상위 5개 중 맞는 것 비율. 목표 0.75 |

## 관련 파일
- `figindex/backend/app/main.py`: 검색 API (`/api/search`, `/api/elements`)
- `figindex/pipeline/orchestrator.py`: 저장할 때 Sparse 토큰을 만드는 부분 (Kiwi 형태소 분석)
- `figindex/data/entity_dictionary.csv`: 엔티티 사전 (지금 1건)
- `figindex/data/analysis/targets.csv`: 우리 데이터에 있는 종목 47개
- `docs/glossary.md`: 10절(엔티티 사전), 11절(데이터셋 이름), 12절(지표)

## 할 일
| 단계 | 할 일 | 확인 방법 |
| --- | --- | --- |
| 1 | Swagger(localhost:8000/docs)에서 `/api/search`에 검색어 10개를 넣고 결과 기록 | 검색어별 "상위 5개 중 맞는 개수" 표 |
| 2 | 엔티티 사전 채우기: `targets.csv`의 47개 종목을 `entity_name,entity_type,aliases,ticker` 형식으로 | CSV 47줄 이상, 별칭은 확실한 것만 |
| 3 | 검색 정답셋 20개: 사용자가 칠 법한 검색어 20개 + 각 검색어에 맞는 `element_id` 목록. 1단계 기록을 출발점으로 | `data/gt/search/queries.json` |
| 4 | AI에게 지금 검색 코드를 그림처럼 설명받고, 검색에 Sparse를 더해 하이브리드로 바꾸기 | 1단계 검색어 10개를 다시 넣고 전후 비교 |
| 5 | 검색어 속 별칭을 대표 이름으로 바꿔 `entities` 필터에 연결, `APPROVED`만 나오는지 확인 | "하이닉스"로 검색해도 SK하이닉스 결과가 위에 |
| 6 | AI에게 정답셋으로 `precision_at_5`, `search_latency_sec`를 재는 스크립트를 만들게 하고 실행 | 두 숫자를 팀장에게 보고 |

### 3단계 검색 정답셋 형식
```json
[{"query": "SK하이닉스 영업이익 전망",
  "relevant_element_ids": ["...", "..."]}]
```
- 검색어는 시연에서 실제로 칠 만한 것 위주로: 회사명+지표, 지표만, 산업+지표 섞어서
- 맞는 요소는 화면에서 직접 확인하고 `element_id`를 복사 (상세 페이지 주소 끝에 있음)

## 완료 기준
- `precision_at_5` ≥ 0.75
- 검색 응답 1초 이내

## 하면 안 되는 것
- `figindex_elements_v2`에 쓰기·삭제. 색인을 다시 만들어야 하면 시험용 컬렉션에서 하고 팀장 승인 후 교체
- 사전에 확실하지 않은 별칭 넣기 (다른 회사와 섞임)
- 정답셋을 검색 결과에 맞춰 고치기 (점수가 부풀려짐)
