# 역할 브리핑: 팀원 B (추출 품질·정답셋)

> AI에게: 이 사용자는 프로젝트에 처음 참여했고 코딩이 익숙하지 않다. 한 번에 한 단계씩, 코드를 쓰기 전에 무엇을 왜 하는지 먼저 설명한다. 각 단계는 사용자가 직접 실행하고 눈으로 확인하게 한다. 루트 `AGENTS.md`와 `figindex/pipeline/AGENTS.md`를 따른다.

## 한 줄 요약
AI(Gemini)가 표 이미지를 보고 읽어 낸 숫자가 **원문과 정말 같은지** 확인하는 일입니다. 이를 위해 "정답지(정답셋)"를 만들고, AI 결과를 정답지와 비교해 점수를 냅니다.

## 전체에서 내 위치
`PDF 업로드 → 오려 내기 → ★AI가 내용 읽기 → 확신도 계산★ → 저장 → 검색`

## 왜 중요한가
이 서비스는 "여러 증권사 리포트의 같은 숫자를 나란히 비교"하는 게 핵심입니다. 숫자 하나가 틀리면 비교 자체가 무의미해집니다. 정답셋이 있어야 "우리 시스템이 몇 % 맞힌다"고 말할 수 있고, 발표의 근거가 됩니다.

## 알아야 할 말
| 말 | 뜻 |
| --- | --- |
| 요소(element) | 표·차트·다이어그램 하나. 화면의 카드 하나 |
| TableData | AI가 표를 읽어 만든 결과. `columns`(열 이름), `rows`(행들), `unit`(단위) |
| 정답셋 | 사람이 원문을 보고 직접 만든 "진짜 답". AI 결과를 채점하는 기준 |
| 확신도 | AI 결과를 얼마나 믿을 수 있는지 0~1 점수. 0.80 미만이면 사람 검수로 보냄 |
| cell_accuracy | 정답셋 숫자 칸 중 AI가 맞힌 비율. 목표 0.95 |
| 오분류 | 표를 차트로, 로고를 표로 잘못 분류한 것 |

## 관련 파일
- `docs/glossary.md`: 2절(유형 구분), 6절(확신도 신호), 7절·9절(표 숫자·단위 저장 규칙), 11절(데이터셋 이름), 12절(지표)
- `figindex/shared/schemas.py`: `TableData`, `ConfidenceSignals`
- `figindex/pipeline/extractor.py`: Gemini에게 표를 읽히는 코드
- `figindex/pipeline/evaluator.py`: 확신도 계산 코드

## 할 일
| 단계 | 할 일 | 확인 방법 |
| --- | --- | --- |
| 1 | 웹 화면에서 표 카드 10개를 열고 [원문 보기]로 원본과 숫자를 비교 | 틀린 숫자·단위를 시트에 기록 (오분류도 같이) |
| 2 | glossary 7절·9절의 숫자 저장 규칙을 AI에게 예시로 설명받기 (`△1.2` → `-1.2` 등) | 규칙을 내 말로 3줄 요약 |
| 3 | 수치 정답셋용 표 30개 고르기: 같은 종목을 여러 증권사가 다룬 표 위주 (`figindex/data/analysis/targets.csv` 참고) | 30개 `element_id` 목록을 팀장에게 공유 |
| 4 | 표마다 정답 JSON 만들기 (아래 방법) | `data/gt/table/`에 30개 파일 |
| 5 | 검색 정답셋: 사용자가 칠 법한 검색어 20개 + 각 검색어에 맞는 `element_id` 목록 | `data/gt/search/queries.json` |
| 6 | AI에게 `cell_accuracy`, `table_valid_rate` 계산 스크립트를 만들게 하고 실행 | 두 숫자를 팀장에게 보고 |
| 7 | (병합 후) 신호3 "수치 정합성" 점검: 합계 행이 실제 합과 맞는지 확인하는 코드 개선 | 정답셋 표로 점수가 맞게 나오는지 확인 |

### 4단계 정답 JSON 만드는 방법
- 처음부터 쓰지 않습니다. AI에게 "이 `element_id`의 현재 `table_data`를 `data/gt/table/{element_id}.json`으로 복사해 줘"라고 시킵니다.
- 원문 PDF 페이지를 옆에 띄워 놓고 **틀린 칸만** 고칩니다.
- 고칠 때도 glossary 7절 규칙대로: 쉼표 없이 숫자, 음수는 `-`, 단위는 셀이 아니라 `unit`에.

## 완료 기준
- `table_valid_rate` ≥ 0.90, `cell_accuracy` ≥ 0.95
- 정답셋 3종 중 수치(30개)·검색(20개) 완성

## 팀장과 같이 하는 것
- 프롬프트 수정, 신호4(2번 읽혀서 비교), 확신도 가중치 조정은 결과에 큰 영향을 주므로 팀장과 함께 결정합니다.

## 하면 안 되는 것
- 프롬프트를 바꾸고 그냥 넘어가기 (→ "`PIPELINE_VERSION` 올려야 함"이라고 보고)
- 가중치 조정에 쓴 표로 `cell_accuracy`를 다시 재기 (점수가 부풀려짐)
- 유료 API 사용
